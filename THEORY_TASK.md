**1)** Пусть на вход дан сигнал x[n], а на выход нужно дать два сигнала y1[n] и y2[n]:

```
 y1[n] = x[n - 1] + x[n] + x[n + 1]
 y2[n] = y2[n - 2] + y2[n - 1] + x[n]
```

Какой из двух сигналов будет проще и быстрее реализовать в модели массового параллелизма на GPU и почему?

**Ответ:** Первый сигнал

**Решение:** Первый сигнал зависит только от входного x, так же доступ памяти будет coalesced так как соседние потоки обращаются к соседним элементам.
Второй сигнал лучше, чем в один поток, считать сложно, так как, чтобы посчитать элемент n у нас должны быть посчитаны все до этого 

**2)** Предположим что размер warp/wavefront равен 32 и рабочая группа делится
на warp/wavefront-ы таким образом что внутри warp/wavefront
номер WorkItem по оси x меняется чаще всего, затем по оси y и затем по оси z.

Напоминание: инструкция исполняется (пусть и отмаскированно) в каждом потоке warp/wavefront если хотя бы один поток выполняет эту инструкцию неотмаскированно. Если не все потоки выполняют эту инструкцию неотмаскированно - происходит т.н. code divergence.

Пусть размер рабочей группы (32, 32, 1)

```
int idx = get_local_id(1) + get_local_size(1) * get_local_id(0);
if (idx % 32 < 16)
    foo();
else
    bar();
```

Произойдет ли code divergence? Почему?

**Ответ:** Не произойдет

**Решение:** get_local_size(1) = 32, поэтому второе слагаемое в idx не влияет на остаток на 32.
Так как в warp у нас 32 потока и сначала мы меняем координату по оси x, то во всех 32
потоках warp`а у всех будет одинаковая координата по y, и code divergence не произойдет

Пусть размер рабочей группы (32, 32, 1).
Пусть data - указатель на массив float-данных в глобальной видеопамяти идеально выравненный (выравнен по 128 байтам, т.е. data % 128 == 0). И пусть размер кеш линии - 128 байт.

(a)
```
data[get_local_id(0) + get_local_size(0) * get_local_id(1)] = 1.0f;
```

Будет ли данное обращение к памяти coalesced? Сколько кеш линий записей произойдет в одной рабочей группе?

**Ответ:**  Coalesced, 32

**Решение:** Каждый warp выглядит как строка с одинаковыми get_local_id(1), get_local_size(0) - константа
get_local_id(0) будет в warp от 0 до 31, по номеру потоков, поэтому мы обращаемся к 32 подряд лежащим float, т.е.
к 32 * 4 = 128 байтам подряд, то есть к одной кеш линии, в workgroup будет 32 warp, а значит обратимся к 32 кеш линиям

(b)
```
data[get_local_id(1) + get_local_size(1) * get_local_id(0)] = 1.0f;
```

Будет ли данное обращение к памяти coalesced? Сколько кеш линий записей произойдет в одной рабочей группе?

**Ответ:** Не coalesced, 32 * 32 = 1024

**Решение:** get_local_size(1) = 32, поэтому в одной warp-строке мы будем делать шаг размера 32, то есть будем
каждый раз бить в разные кеш-линии, 32 warp по 32 кеш-линии дадут 1024 обращения к кеш-линиям

(c)
```
data[1 + get_local_id(0) + get_local_size(0) * get_local_id(1)] = 1.0f;
```

Будет ли данное обращение к памяти coalesced? Сколько кеш линий записей произойдет в одной рабочей группе?

**Ответ:** Почти coalesced, 64 линии

**Решение:** Имеем, то же самое, что и в пункте 1, но со сдвигом на 1, поэтому warp не хватит
одной кеш-линии и придется задействовать 2. 32 warp по 2 кеш-линии даст нам 64 кеш-линии
